## 1. Introduction

This project focuses on building an animal detection and counting system for the Deep Learning final project. Given a single input image, the system is required to recognize the animal categories appearing in the image and count the number of instances for each category. The final output must be a clean Python-style dictionary or JSON object, such as `{"cat": 2, "duck": 1}`, where each key is an animal category and each value is a positive integer count. Therefore, the task is not a simple image classification problem, but a structured image understanding task that combines object detection, category filtering, instance counting, and machine-readable output formatting.

The evaluation categories are limited to 20 animal classes: `cat`, `dog`, `horse`, `cow`, `sheep`, `goat`, `pig`, `rabbit`, `chicken`, `duck`, `goose`, `deer`, `monkey`, `fox`, `wolf`, `bear`, `tiger`, `lion`, `zebra`, and `giraffe`. The system should only output categories that are actually detected in the image, and non-animal objects such as people, cars, trees, cages, or background items must not appear in the prediction dictionary. In addition, categories with zero count should be omitted to ensure that every prediction satisfies the required output format.

To solve this problem, we developed a YOLO-based detection and counting pipeline. The system uses a YOLO detector to obtain bounding boxes, confidence scores, and class labels from each input image. Then, a predefined animal category whitelist is applied to remove unsupported or non-animal predictions. After confidence filtering and duplicate handling through YOLO's post-processing, the remaining detections are grouped by category and counted. Finally, the counts are converted into a sorted dictionary and written to JSON for batch evaluation.

Besides single-image prediction, the project also implements a batch evaluation workflow. The batch script processes all images in an evaluation folder, runs the animal counter independently on each image, and saves the results in the required JSON format using image file names as keys. This design ensures that the system can be used both for validation-set debugging and for the final synthetic evaluation set released by the teaching assistants. The overall goal of our project is to build a reproducible, efficient, and format-safe animal counting system that balances detection accuracy with strict output validity.

## 2. Methodology

### 2.1 Dataset Construction

We constructed the training data from three complementary sources. The first source was a collection of public real-world animal detection datasets. These datasets originally used different folder structures, label IDs, and sometimes different class names, so we reorganized them into one unified YOLO-format dataset with the 20 animal categories required by the project. During this process, only the target animal categories were kept, while irrelevant classes and invalid label rows were removed. Similar or fine-grained labels were also merged into the project categories, such as mapping different bear labels to `bear`, cattle-related labels to `cow`, and wild boar to `pig`.

The second source was an AI-generated single-animal dataset. This dataset was used to improve category coverage and provide cleaner examples for animal appearance. The final usable set contained 787 images after removing low-quality samples, and it was split into training and validation subsets with an approximately 8:2 ratio. Each image was converted into YOLO detection format by estimating the visible animal region and writing a bounding-box label for the corresponding class.

The third source was a synthetic multi-animal dataset generated from AI animal assets and background images. We composed animals from the 20 target classes onto varied backgrounds to simulate images containing multiple animal instances and multiple species. This part was important because the final task evaluates not only category recognition, but also instance counting. The synthetic dataset contains 3,500 images, including 2,800 training images and 700 validation images, with 16,345 total animal instances. We also added focused samples for classes that required more counting practice, including `cow`, `goat`, `chicken`, `duck`, and `zebra`.

| Data Source | Purpose | Scale | Notes |
|---|---|---|---|
| Public real-world animal datasets | Base detection training | Covers all 20 classes | Cleaned and converted to unified YOLO labels |
| AI-generated single-animal dataset | Improve category coverage | 787 usable images | 8:2 train/validation split |
| Synthetic multi-animal dataset | Improve multi-instance counting | 3,500 images / 16,345 instances | 2,800 train and 700 validation images |

### 2.2 Data Preprocessing and Augmentation

All datasets were converted into a consistent 20-class YOLO detection format. Each annotation line contains a class ID and a normalized bounding box represented by the center coordinates, width, and height. Since different source datasets used different class IDs and class names, we built a category-mapping step to align all labels with the final project category list. This preprocessing step ensured that the model learned the same class order as the required output dictionary.

For the real-world datasets, labels outside the required animal categories were filtered out. For the AI-generated data, we removed samples where the animal was unreadable, abnormally segmented, or too heavily occluded to provide a reliable training target. In the synthetic multi-animal generation process, the animal masks were also checked after placement. Animals that became almost invisible after overlap or cropping were excluded from the final labels, which reduced noisy annotations and helped the model learn more reliable counting behavior.

Data augmentation was applied to improve robustness. We used YOLO's built-in augmentation strategy, including Mosaic, random scaling, translation, horizontal flipping, color variation, random erasing, and noise-like perturbations. In the synthetic data generation process, we also introduced controlled resizing, light rotation, brightness and contrast changes, edge blending, and background variation. These operations increase diversity in object scale, pose, illumination, and scene layout, which is especially useful for small animals, partially occluded animals, and multi-species images.

### 2.3 Model Selection and Training

We selected YOLO26x as the final detector and initialized it with pretrained YOLO weights. We also tested the smaller YOLO26n model as a baseline, but YOLO26x produced better detection results after training, especially for visually similar categories and multi-animal scenes. Although YOLO26x is larger, the final evaluation only requires batch inference on a fixed image set, so the higher detection quality was more important than the smallest possible model size.

The training process was divided into two stages. In the first stage, the model was trained on the unified real-world animal dataset so that it could learn general animal appearance from natural images. In the second stage, the trained model was further fine-tuned on the synthetic multi-animal dataset to improve its ability to detect multiple animals in one image and handle the synthetic style of the final evaluation set. Both stages used an image size of 640 and a batch size of 8. The main training setting was 80 epochs for the first stage and 40 epochs for the second, while the optimizer, learning-rate schedule, and other low-level hyperparameters were handled by YOLO's automatic configuration.

| Item | Setting |
|---|---|
| Final detector | YOLO26x |
| Initial weight | Pretrained YOLO weight |
| Training strategy | Real-world animal data followed by synthetic multi-animal fine-tuning |
| Image size | 640 |
| Batch size | 8 |
| Epochs | 80 for the real-world stage and 40 for the synthetic stage |

| Final saved model | Best fine-tuned model used for validation and evaluation prediction |

### 2.4 Detection and Counting Pipeline

The inference system takes one image path as input and returns an animal-count dictionary. First, the image is loaded and passed to the trained YOLO detector. The detector predicts bounding boxes, confidence scores, and class labels for possible animal instances. Low-confidence predictions are removed according to the selected confidence threshold. The model's built-in post-processing, including non-maximum suppression, is used to reduce duplicate boxes that refer to the same animal instance.

After detection, we apply an animal whitelist that contains only the 20 project categories. Any prediction whose label is not in this list is discarded, which prevents non-animal objects or unsupported categories from entering the final result. The remaining detections are then grouped by animal category. The number of detections in each group becomes the predicted count for that animal. Finally, the result is formatted as a dictionary containing only observed categories with positive integer counts.

```text
Input image
-> YOLO detector
-> confidence filtering
-> animal category whitelist
-> NMS / duplicate removal
-> group detections by category
-> count instances
-> output dictionary / JSON
```

### 2.5 Output Format and Batch Evaluation Script

To satisfy the evaluation requirement, the system outputs only structured data. For a single image, the output is a dictionary such as `{"cat": 2, "duck": 1}`. The keys are English animal category names, and the values are positive integer counts. Categories with count 0 are not included, and natural-language explanations are never written into the prediction result.

For final evaluation, we implemented a batch prediction script. It reads all images from a given folder, runs the same single-image counting pipeline independently on each image, and writes one JSON file. In this JSON file, each key is the image file name and each value is the corresponding animal-count dictionary. If no supported animal is detected in an image, the value is an empty dictionary `{}` so that every input image still has a valid prediction entry.

Example batch output:

```json
{
  "eval_000001.png": {"cat": 2, "duck": 1},
  "eval_000002.png": {"bear": 1},
  "eval_000003.png": {}
}
```

## 3. Evaluation Result

We evaluated the system from two perspectives. First, we checked the standard YOLO detection metrics on the training validation split, including precision, recall, mAP50, and mAP50-95. These metrics measure whether the detector can localize and classify animal instances correctly. Second, we evaluated the complete project pipeline using the official dictionary-based scoring rule, which directly measures whether the final JSON output contains the correct animal categories and counts.

On the YOLO validation split, the model trained on the unified real-world animal dataset reached a best mAP50 of 0.88148, with precision 0.90245, recall 0.81575, and mAP50-95 0.76441. After further fine-tuning on the synthetic multi-animal dataset, the model achieved a best mAP50 of 0.99499, with precision 0.99413, recall 0.99757, and mAP50-95 0.99104. Another training run on the synthetic dataset also reached mAP50 0.99499, but the final submission focused on the stronger YOLO26x-based model and the best fine-tuned checkpoint.

For the project score, we used the small initial validation set only for early debugging and format checking. The final evaluation set contained 500 images, and its average score is the final accuracy announced for the project. The pretrained baseline models in the root directory performed much worse than the fine-tuned model because they were not trained for all 20 project categories and were less reliable on synthetic multi-animal images.

| Model / Setting | Confidence | Evaluation Set | Average Score |
|---|---:|---|---:|
| Pretrained YOLO26n baseline | 0.25 | Small initial validation set | 31.83 |
| Pretrained YOLO26x baseline | 0.25 | Small initial validation set | 38.94 |
| YOLO26x trained on real-world animal data | 0.10 | Final evaluation set | 47.59 |
| Final fine-tuned model | 0.70 | Final evaluation set | 77.99 |

The comparison shows that increasing the model size from YOLO26n to YOLO26x improved the baseline result, but the main improvement came from task-specific training. The real-world animal dataset helped the model learn the 20 required animal categories, while the synthetic multi-animal fine-tuning stage improved its ability to handle multiple species and multiple instances in one image. As a result, the final model achieved a final accuracy of 77.99 on the 500-image final evaluation set.

We also tuned the confidence threshold because it directly affects the trade-off between missing animals and producing extra wrong categories. A lower threshold increases recall and detects more animals, but it also introduces more false positives. A higher threshold reduces false positives, but may miss small, distant, or partially occluded animals. On the final evaluation set, the fine-tuned model achieved the best average score around confidence 0.70, so this setting was selected for the final JSON prediction file.

Finally, we checked the validity of the submitted JSON file. The final key-matched prediction file contained 500 prediction entries, exactly matching the 500 image keys in the final evaluation ground truth. There were no missing image entries and no extra image entries. The JSON file could be parsed correctly, and the prediction values followed the required dictionary format with only supported animal categories and positive integer counts.

Typical successful cases were images containing several clearly visible animals from different categories, where the final model could detect most species and count repeated instances more accurately than the baseline models. The remaining errors mainly came from visually similar categories, small or occluded animals, and crowded scenes where several animals overlapped. These errors directly affected the category-recognition score and the counting score, which are analyzed further in the next section.

## 4. Analysis

### 4.1 Challenges

The first challenge was the visual similarity among several animal categories. For example, `duck`, `goose`, and `chicken` share similar shapes in synthetic images; `fox`, `wolf`, and `dog` can be confused because of similar body structure; and large cats such as `tiger`, `lion`, and `cat` may have overlapping visual features when image scale or texture is unclear. These confusions directly affect the category-recognition part of the score.

The second challenge was multi-object counting. Many final evaluation images contain several animals from different categories, and some images contain repeated instances of the same category. When animals are small, partially occluded, or overlapping with each other, the detector may miss instances or count one animal more than once. This makes the counting part of the task harder than simple single-object detection.

The third challenge was the domain gap between real-world training images and the synthetic final evaluation set. Real animal datasets contain natural lighting, camera perspective, and background context, while the final evaluation images are synthetic and may show different textures, object boundaries, and composition styles. A model trained only on real images therefore may not generalize well to the final evaluation distribution.

Another practical challenge was the cost of annotating AI-generated data. Directly generating complete multi-animal images and manually annotating every animal instance would require a large amount of time. Finally, the confidence threshold also required careful tuning. A low threshold improves recall but may introduce extra wrong categories, while a high threshold reduces false positives but may miss small or occluded animals.

### 4.2 Solutions

To reduce confusion between similar categories, we constructed training samples that included visually related animals and forced the model to learn their differences under the same detection framework. The unified 20-class label space also helped avoid inconsistent category definitions across different data sources.

To improve multi-animal counting, we generated training images containing multiple animals, multiple categories, small objects, partial occlusion, and overlap. These samples made the training data closer to the final task, where the model must detect every visible animal instance and count each category separately.

To reduce the domain gap, we added AI-generated animal data and synthetic background compositions. Instead of directly generating complete scenes and manually annotating all boxes, we first generated single-animal assets, estimated or annotated their visible regions, and then randomly composed animals with different backgrounds. This strategy allowed us to create a large number of labeled multi-animal images with much less manual annotation effort.

For post-processing, we used an animal-category whitelist to prevent unsupported or non-animal predictions from entering the JSON output. We also relied on YOLO's built-in non-maximum suppression to reduce duplicate detections. For the confidence threshold, we evaluated multiple settings according to the project scoring rule and selected 0.70 for the final model because it achieved the best final evaluation accuracy.

### 4.3 Error Analysis

We analyzed the final model on the 500-image final evaluation set. The ground truth contained 1,807 category entries in total. The model correctly recognized 1,624 of these categories, giving a category-level recall of about 89.9%. Among all ground-truth category entries, 1,265 had both the correct category and the correct count, which is about 70.0%. This shows that the model was generally good at recognizing whether a category appeared, but exact counting remained more difficult.

| Error Type | Main Observation | Possible Cause | Improvement Direction |
|---|---|---|---|
| Missing detection | Most frequent missing categories included `dog` (38), `monkey` (31), `goat` (30), `duck` (18), and `cat` (16). | Small scale, occlusion, or synthetic appearance different from training examples. | Add more small-object and occluded examples for these categories. |
| Extra wrong category | The most frequent extra predictions were `goose` (71), `cow` (22), `cat` (22), `duck` (19), and `lion` (17). | Similar shapes or textures caused the model to over-predict some categories. | Add harder negative examples and tune class-specific thresholds. |
| Wrong count | Count errors were frequent for `horse` (34), `zebra` (27), `chicken` (26), `fox` (22), and `cow` (22). | Multiple same-class animals, overlap, and partial visibility made instance separation difficult. | Add crowded scenes and tune NMS behavior. |
| Category confusion | The most obvious confusion was `duck` predicted as `goose`; other examples included `goat/cow`, `dog/lion`, and `dog/wolf`. | Fine-grained species differences were not always clear in synthetic images. | Train with paired confusing categories in the same scene. |

These errors are closely related to the scoring rule. Recognizing the correct category gives only half of the category score, while predicting the exact count gives the remaining half. Extra wrong categories also reduce the score. Therefore, improving both category precision and count accuracy is necessary for further improvement.

### 4.4 Limitations and Future Work

The main limitation of our data construction method is that compositing AI-generated animal assets onto backgrounds is not identical to generating a complete natural scene directly. Although this method can produce many labeled images with relatively little manual annotation, the object boundaries, lighting, shadows, and occlusion relationships may still look different from fully generated images. This gap likely limited the final accuracy.

In future work, we would generate complete multi-animal scenes directly with AI tools and manually annotate a smaller but higher-quality subset. We would then mix these full-scene synthetic images with real animal datasets to improve both synthetic-image adaptation and generalization. We would also add more targeted samples for confusing category pairs, small animals, and crowded scenes. On the post-processing side, class-specific confidence thresholds, NMS tuning, confidence calibration, or model ensembling could further reduce false positives and improve counting accuracy.

## 6. Conclusion

In this project, we implemented a YOLO-based animal detection and counting system that converts input images into structured animal-count dictionaries. The system supports the 20 animal categories required by the project and integrates the full workflow from image loading to final JSON generation. Specifically, it uses a trained YOLO detector, confidence filtering, animal-category whitelisting, non-maximum suppression, category grouping, and batch prediction to produce valid outputs without natural-language explanations. To improve model performance, we constructed and cleaned real-world animal data, AI-generated single-animal data, and synthetic multi-animal data, then trained the model in two stages using real animal images followed by synthetic multi-animal fine-tuning.

The final fine-tuned model achieved a final accuracy of 77.99 on the 500-image final evaluation set, and the submitted JSON file matched all 500 image keys with a valid dictionary format. Compared with the pretrained baseline models, the final result shows that task-specific data construction and synthetic multi-animal fine-tuning were effective for this animal counting task. However, the system still has limitations. The main remaining errors come from similar animal categories, small or occluded animals, crowded scenes, and the gap between composited AI training images and complete natural synthetic scenes. In future work, we would generate full multi-animal scenes directly and annotate them manually, mix them with real animal datasets, add more samples for confusing categories and small objects, and further optimize thresholds, NMS settings, or model ensembling to improve both category precision and counting accuracy.
