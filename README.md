# Final Project: Animal Detection and Counting

本项目是深度学习课程 Final Project，目标是构建一个动物识别与计数系统。系统输入一张图片，输出一个机器可读的字典或 JSON，表示图片中出现了哪些动物，以及每种动物的数量。

项目推荐使用 YOLO 作为核心目标检测模型，但最终评分关注的是完整系统能否稳定地输出符合要求的动物计数字典，而不仅仅是模型是否能画出检测框。

## 1. 项目目标

你需要完成一个 image understanding system，用于 animal recognition and counting。

对于单张输入图片，系统应输出类似下面的结果：

```json
{
  "cat": 2,
  "duck": 1,
  "deer": 1
}
```

这个结果表示系统在图片中检测到 2 只猫、1 只鸭和 1 只鹿。

最终项目由三部分组成：

1. 构建或收集训练数据，用于提升模型表现。
2. 实现动物检测与计数系统。
3. 在验证集和最终评测集上生成 JSON 预测文件，并提交报告、代码和展示 PPT。

## 2. 最终输出要求

系统最终输出必须满足以下规则：

1. 输出必须是字典或 JSON 对象。
2. key 必须是动物类别英文名。
3. value 必须是该动物类别在图片中的数量。
4. 数量必须是大于或等于 1 的整数。
5. 只输出图片中实际检测到的动物，不要输出数量为 0 的类别。
6. 只能输出动物类别，不能输出 `person`、`car`、`chair`、`tree`、`cage` 等非动物类别。
7. 一张图片可能包含多个动物类别，系统需要分别计数。
8. 最终评测 JSON 中不要包含自然语言解释。

单张图片预测可以表示为：

```json
{
  "cat": 2,
  "duck": 1
}
```

批量评测文件应表示为：

```json
{
  "eval_000001.png": {"cat": 2, "duck": 1, "deer": 1},
  "eval_000002.png": {"cat": 2, "bear": 2, "deer": 1},
  "eval_000003.png": {"dog": 2, "duck": 1, "deer": 2}
}
```

## 3. 支持的动物类别

## 4. 从零开始的完成流程

### 4.1 理解任务与准备目录

首先阅读 `Final_Project_task.pdf`，明确项目不是普通分类任务，而是目标检测、类别过滤、实例计数和 JSON 格式化的组合任务。

建议保持项目目录清晰，例如：

```text
Final Project/
  datasets/       # 自建或下载的数据集
  models/         # 训练好的模型权重
  outputs/        # 预测结果、日志、可视化结果
  src/            # 核心代码
  val_set/        # 老师提供的小验证集
  main.py
  README.md
```

当前项目已经包含 `val_set/`，其中有验证图片和 `ground_truth.json`。这个验证集只用于调试流程和检查格式，不是最终评分集。

### 4.2 明确系统输入输出

在写模型代码前，应先确定系统接口：

1. 输入：单张图片路径。
2. 输出：一个字典，例如 `{"cat": 2, "duck": 1}`。
3. 批量输入：一个图片文件夹。
4. 批量输出：一个 JSON 文件，key 为图片文件名，value 为该图片的预测字典。

这样可以保证后续无论使用预训练 YOLO、微调 YOLO，还是其他检测方法，都能接入同一个输出格式。

### 4.3 选择基础模型

PDF 推荐使用 YOLO。通常可以从预训练 YOLO 模型开始，例如 YOLOv8、YOLOv9、YOLOv10、YOLOv11 或其他可用版本。

从零开始时建议按以下顺序推进：

1. 先跑通预训练 YOLO 的推理流程。
2. 查看预训练模型能识别哪些动物类别。
3. 建立模型类别到项目评测类别的映射。
4. 在 `val_set/` 上生成预测 JSON。
5. 对比 `ground_truth.json`，分析漏检、误检和计数错误。
6. 再决定是否需要收集数据并微调模型。

### 4.4 建立动物类别白名单

系统必须只输出规定动物类别，因此需要建立 animal category whitelist。

白名单应只包含第 3 节列出的 20 个类别。推理时，模型输出的类别如果不在白名单内，就应过滤掉。

如果模型类别名和项目类别名不完全一致，需要建立映射。例如某些模型可能使用不同的命名方式，或者没有 `goose`、`duck`、`deer` 等类别。映射关系应在报告中说明。

### 4.5 实现单张图片检测流程

单张图片预测流程应包括：

1. 读取图片。
2. 将图片转换为模型需要的输入格式。
3. 运行 YOLO 或其他检测模型。
4. 获得 bounding boxes、confidence scores 和 class labels。
5. 过滤掉非动物类别。
6. 过滤掉低置信度检测框。
7. 进行重复框处理，避免同一只动物被重复计数。
8. 按动物类别分组。
9. 统计每个类别的实例数量。
10. 返回干净的字典。

在这个阶段，重点不是追求最高准确率，而是确保系统能稳定返回合法格式。

### 4.6 调整置信度阈值

置信度阈值会影响漏检和误检：

1. 阈值过高：可能漏掉小动物、遮挡动物或远处动物。
2. 阈值过低：可能把背景物体或错误类别也算进去。

建议在验证集上尝试多个阈值，并记录不同阈值下的表现。报告中可以说明最终阈值的选择依据。

### 4.7 处理重复检测

目标检测模型可能对同一只动物输出多个相近的框。为了避免重复计数，需要使用 non-maximum suppression，或使用模型自带的后处理结果。

检查重复检测时，可以把预测框可视化保存到 `outputs/`，人工观察哪些错误来自重复框，哪些错误来自类别识别错误。

### 4.8 实现批量评测脚本

最终评测时，老师会发布一整个评测图片文件夹，要求在短时间内提交 JSON。因此必须提前写好批量脚本。

批量脚本应完成：

1. 读取指定文件夹中的所有图片。
2. 对每张图片独立运行单张图片预测流程。
3. 用图片文件名作为 JSON 的 key。
4. 用该图片的预测字典作为 value。
5. 将全部结果写入一个 JSON 文件。
6. 确保 JSON 中没有自然语言解释、日志文本或非法类别。

建议在 `val_set/` 上反复测试批量脚本，确认输出格式正确。

### 4.9 使用验证集检查流程

老师提供的小验证集大约有 10 张图片，当前项目中的验证集位于：

```text
val_set/
```

其中：

```text
val_set/ground_truth.json
```

包含验证图片的标准答案。

验证集用途：

1. 检查图片读取是否正常。
2. 检查模型推理流程是否正常。
3. 检查动物类别过滤是否正常。
4. 检查字典和 JSON 输出格式是否正确。
5. 初步估计系统的类别识别和计数效果。

注意：验证集不是最终评分集。不能只针对验证集调规则，应尽量提升系统在未知合成评测集上的泛化能力。

## 5. 数据集构建、标注与训练

这一节单独说明数据收集、数据标注、模型训练和错误分析。PDF 鼓励团队尽可能构建或收集训练数据，以提升模型表现。训练数据不需要作为正式评测数据提交，但报告中必须清楚说明数据构建过程、训练方式和实验分析。

### 5.1 数据集目标

数据集的目标不是简单堆图片，而是让模型更好地完成最终任务：识别指定动物类别，并准确统计每个类别的数量。

因此，数据集应尽量覆盖最终评测可能出现的情况：

1. 单张图片中只有一只动物。
2. 单张图片中有同一类别的多只动物。
3. 单张图片中同时有多个动物类别。
4. 动物之间有遮挡或重叠。
5. 动物尺寸较小，或者出现在远处。
6. 图片中有背景干扰物，例如人、车、笼子、树、草地、水面、建筑物等。
7. 动物姿态、光照、拍摄角度和背景尽量多样。

### 5.2 数据来源

可以混合使用多种数据来源：

1. 公开动物检测数据集。
2. 自己从网络或现实场景中收集的动物图片。
3. 老师提供的验证集之外的自建图片。
4. 数据增强生成的新样本。
5. 人工合成或半合成图片。

使用公开数据集时，要注意类别是否覆盖项目要求的 20 个动物类别。如果公开数据集中的类别名和项目类别名不一致，需要在数据处理阶段建立映射，并在报告中说明。

使用自己收集的图片时，应保留来源记录，方便报告中说明数据规模、来源和筛选方法。

### 5.3 数据清洗

收集图片后，建议先进行清洗。清洗的目标是减少无效数据和错误标注对训练的影响。

需要检查：

1. 图片是否能正常打开。
2. 图片是否过小、过模糊或严重损坏。
3. 图片中是否真的包含目标动物。
4. 图片中的动物类别是否属于项目支持的 20 个类别。
5. 是否存在重复图片或高度相似图片。
6. 图片文件名是否规范，是否便于后续脚本处理。

对于质量很差或类别不明确的图片，可以删除或单独放入待确认目录，不建议直接加入训练集。

### 5.4 标注原则

如果需要 fine-tuning YOLO，需要为图片标注 bounding box 和类别。

标注时应遵守：

1. 每只可见动物都应单独标注一个框。
2. 框应尽量贴合动物主体，不要包含过多背景。
3. 被遮挡的动物如果仍能识别，应标注其可见主体区域。
4. 同一张图片中同类别多只动物要分别标注，不能只标一个总框。
5. 不属于 20 个支持类别的动物不要标成支持类别。
6. 非动物目标不要标注。
7. 类别名必须和最终类别列表保持一致，或在训练配置中有清晰映射。

可以使用 LabelImg、CVAT、Roboflow、Label Studio 等工具标注。无论使用哪种工具，最终都要导出为所选 YOLO 版本支持的格式。

### 5.5 YOLO 数据格式

多数 YOLO 训练流程要求每张图片对应一个同名标签文件。标签文件通常包含每个目标的类别编号和归一化后的框坐标。

典型目录结构可以是：

```text
datasets/
  animal_yolo/
    images/
      train/
      val/
    labels/
      train/
      val/
    data.yaml
```

其中：

1. `images/train/` 放训练图片。
2. `images/val/` 放验证图片。
3. `labels/train/` 放训练标签。
4. `labels/val/` 放验证标签。
5. `data.yaml` 记录训练集路径、验证集路径、类别数量和类别名。

训练前应检查图片和标签是否一一对应，类别编号是否从 0 开始，类别顺序是否和 `data.yaml` 中的类别名一致。

### 5.6 数据划分

建议将自建数据划分为训练集和验证集。常见比例是 8:2 或 9:1。

划分时要注意：

1. 同一来源的高度相似图片不要同时大量出现在训练集和验证集。
2. 每个动物类别最好都在训练集和验证集中出现。
3. 稀有类别应尽量保证有足够样本。
4. 验证集不要只包含简单图片，应包含多动物、小目标、遮挡和复杂背景。

老师提供的 `val_set/` 主要用于项目流程和输出格式检查，不建议直接当作训练集使用。

### 5.7 数据增强

数据增强可以提升模型泛化能力，尤其是在自建数据较少时。

可考虑的增强方式包括：

1. 随机缩放。
2. 随机裁剪。
3. 水平翻转。
4. 亮度、对比度、饱和度变化。
5. 模糊或噪声。
6. Mosaic、MixUp 等 YOLO 常用增强。

增强时要避免破坏标签。例如裁剪后如果动物只剩极小部分，可能会造成训练噪声。报告中可以说明使用了哪些增强方法，以及为什么选择这些方法。

### 5.8 训练或微调模型

如果预训练 YOLO 在验证集和自测图片上表现不够好，可以进行 fine-tuning。

训练前需要确认：

1. 数据标注格式是否符合所选 YOLO 版本要求。
2. 类别列表是否与项目的 20 个动物类别一致。
3. 训练集、验证集划分是否合理。
4. 训练配置中的类别数量和类别名是否正确。
5. 预训练权重是否适合作为起点。
6. 训练后的模型权重是否保存到 `models/`。
7. 推理脚本是否能切换到训练后的模型权重。

训练时建议记录：

1. 使用的数据规模。
2. 每个类别的样本数量。
3. 使用的 YOLO 版本和模型规模。
4. 训练轮数。
5. 输入图像尺寸。
6. batch size。
7. 学习率等主要参数。
8. 使用的预训练权重。
9. 训练耗时和硬件环境。

训练后需要保存：

1. 最终模型权重。
2. 最佳模型权重。
3. 训练配置文件。
4. 训练日志或关键指标截图。
5. 若干预测可视化结果。

这些内容应写入项目报告，体现 workload 和 reproducibility。

### 5.9 训练结果评估

训练完成后，不要只看 loss 是否下降，还要检查模型是否真的适合项目评分规则。

建议评估：

1. 是否能识别所有支持动物类别。
2. 是否容易把非动物误检成动物。
3. 是否容易漏掉小动物或远处动物。
4. 同类多只动物时计数是否稳定。
5. 多类别同图时是否能分别计数。
6. 置信度阈值变化对结果的影响。
7. 输出 JSON 是否始终合法。

如果 YOLO 自带指标较好，但最终 JSON 计数仍不准确，应重点检查类别映射、阈值、NMS 和计数逻辑。

### 5.10 错误分析

错误分析是报告中的重要部分，也能帮助提升最终分数。

建议至少分析以下错误类型：

1. 漏检：图片中有动物，但模型没有检测到。
2. 误检：模型把背景或非目标物体识别为动物。
3. 分类错误：模型检测到了动物，但类别预测错。
4. 计数错误：类别正确，但数量不对。
5. 重复计数：同一只动物被统计多次。
6. 小目标错误：远处或很小的动物识别失败。
7. 遮挡错误：动物被部分遮挡时检测失败。
8. 类别映射错误：模型类别名和项目要求类别名没有正确对应。
9. 输出格式错误：预测内容正确，但 JSON 格式或 key 名不符合要求。

报告中可以展示若干典型图片，并说明对应解决方案，例如增加训练数据、平衡稀有类别、调整阈值、改进类别映射、使用更合适的模型权重或优化后处理逻辑。

## 6. 评分规则

最终评测中，每张测试图片 worth 100 points。

如果 ground truth 中有 `N` 个动物类别，则每个类别占：

```text
100 / N
```

对于每个真实类别：

1. 如果类别被正确识别，得到该类别一半分数，即 `50 / N`。
2. 如果该类别的数量也预测正确，再得到另一半分数，即 `50 / N`。

如果预测结果中包含 ground truth 中不存在的动物类别，每多一个错误类别扣 5 分。每张图片最低分为 0 分。

例如 ground truth 是：

```json
{
  "cat": 2,
  "duck": 1,
  "deer": 1
}
```

则 `N = 3`。如果正确识别出 `duck`，可以得到 `50 / 3` 分；如果也正确预测 `duck` 的数量为 1，则再得到 `50 / 3` 分。如果额外错误预测了 `wolf`，则扣 5 分。

## 7. 评测指标

PDF 中提到系统会从以下角度评估：

1. Format validity：输出是否为有效字典，是否只包含动物类别。
2. Category precision：预测出的动物类别是否真的出现在图片中。
3. Category recall：是否检测到了参考答案中的所有动物类别。
4. Counting accuracy：每个动物类别的数量是否正确。
5. Overall response quality：是否能处理完整评测集并返回完整 JSON。

因此，系统不但要追求检测准确，也要保证输出格式稳定。

## 14. 建议完成顺序

建议按下面顺序推进：

1. 阅读 PDF，确认输出格式、动物类别和评分规则。
2. 跑通环境，确认 Python、PyTorch、OpenCV、Pillow 等依赖可用。
3. 选择 YOLO 模型，并完成单张图片推理。
4. 建立动物类别白名单和类别映射。
5. 实现单张图片的检测、过滤、计数和字典输出。
6. 实现批量图片预测和 JSON 写入。
7. 在 `val_set/` 上生成预测 JSON。
8. 对比 `val_set/ground_truth.json`，分析错误。
9. 调整置信度阈值和重复检测处理。
10. 根据错误分析决定是否需要收集或扩充训练数据。
11. 收集、清洗并标注自建数据集。
12. 按 YOLO 要求整理数据目录和配置文件。
13. 训练或微调模型，并保存最终模型权重。
14. 重新在验证集和自测图片上评估结果。
15. 准备报告中的数据构建、方法、实验、错误分析和组员贡献。
16. 准备展示 PPT。
17. 在最终评测前，多次模拟完整流程：输入图片文件夹，输出 JSON。
18. 最终评测图片发布后，直接运行批量脚本并提交 JSON。
19. 最后打包报告、源码和 PPT。
